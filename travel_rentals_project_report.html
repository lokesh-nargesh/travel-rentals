1. Introduction

1.1 Project Overview

The Travel Rentals platform is developed as a comprehensive solution to the fragmented nature of the online travel booking industry. The project’s central goal is to unify the distinct processes of securing car rentals, hotel accommodation, and flight tickets into a single, intuitive, and highly efficient user interface. This holistic approach significantly enhances the travel planning experience by reducing research time and minimizing the risk of booking discrepancies across different systems.

1.1.1 Problem Statement

The current digital landscape for travel planning is characterized by significant inefficiency. Travelers are routinely required to visit three or more distinct vendor or aggregator websites—one for flights, one for hotels, and one for cars. This leads to high cognitive load because users must manage multiple tabs, interfaces, and price comparisons simultaneously. Additionally, personal details must be entered repeatedly across different platforms. Finally, the lack of integration makes it difficult to easily bundle or cross-reference bookings, which often leads to suboptimal travel arrangements (e.g., booking a flight that arrives too late for a car rental pick-up).

1.1.2 Proposed Solution

Travel Rentals offers a dedicated, single point of access for all primary travel needs. The system utilizes modern web technologies and robust data aggregation to present a clear, unified view of available options, ensuring transparency and ease of use. The solution is inherently user-centric, prioritizing fast load times, mobile responsiveness, and an engaging booking flow.

1.2 Scope and Objectives

The initial scope of the Travel Rentals platform focuses on the core functionality of booking car rentals, hotel reservations, and commercial airline tickets. Out of scope for the current iteration are ancillary services such as travel insurance, activity bookings, cruise line reservations, and multi-modal public transit planning. The primary objectives are to develop and deploy a fully functional MVP with clean, responsive front-end pages, implement cohesive cart coordination, and secure payment simulation through tokenization.

2. System Analysis and Requirements

2.1 Functional Requirements (FR)

2.1.1 FR 1: User Management

  • FR 1.1: The system shall allow users to register and create a profile.
  • FR 1.2: The system shall provide features for profile updates (name, email) and password modification.
  • FR 1.3: The system shall store payment methods securely using credit card tokenization simulation.

2.1.2 FR 2: Car Rental Module

  • FR 2.1: The system shall allow users to search for cars by location, pickup/drop-off dates, and pickup time.
  • FR 2.2: The system shall filter results by vehicle class (SUV, Sedan, Hatchback), transmission (Automatic, Manual), and fuel type (Petrol, Diesel, Electric).
  • FR 2.3: The system shall calculate the total rental cost, including taxes based on check-out dates.

2.1.3 FR 3: Hotel Booking Module

  • FR 3.1: The system shall allow users to search for hotels by destination, check-in/out dates, and number of guests.
  • FR 3.2: The system shall display verified ratings and detailed amenities checks (Pool, Gym, Spa, Beach Access).
  • FR 3.3: The system shall display hotel-specific room types and calculate pricing.

2.1.4 FR 4: Flight Booking Module

  • FR 4.1: The system shall search for flights based on origin, destination, dates, and seat class (Economy, Business, First Class).
  • FR 4.2: The system shall display layover segments, airline codes, and real-time status (On Time, Delayed).
  • FR 4.3: The system shall support real-time price tracking, triggering toast notifications upon price fluctuations.

2.1.5 FR 5: Transaction and Confirmation

  • FR 5.1: The system shall process checkout transactions using saved token cards or new cards.
  • FR 5.2: The system shall generate detailed booking confirmations containing dynamic unique receipt IDs.
  • FR 5.3: The system shall provide a dashboard to print travel vouchers.

2.2 Non-Functional Requirements (NFR)

  • NFR 1: Performance: Search results must update instantly on the client side, maintaining transitions under 200ms.
  • NFR 2: Security: Credentials and payment details must be stored securely using client-side sandboxed local storage to ensure no raw numbers are stored.
  • NFR 3: Usability: Conforms to accessibility contrast guidelines, featuring a premium glassmorphic UI with CSS transitions and a dedicated printable print-sheet layout.

3. System Architecture and Design

3.1 Logical Architecture Model

The Travel Rentals platform adopts a modern client-side MVC architecture, mapping logic and views into a decoupled Three-Tier Model (Presentation, Application Logic, Database Storage). This ensures modular development and local persistence.

graph TD A[Client Browser HTML5/CSS3] -->|Interaction Events| B[Logic Controllers: app.js, auth.js] B -->|CRUD Actions| C[Mock DB Engine: db.js] C -->|JSON Serialization| D[(LocalStorage DB)]

3.2 Technology Stack

  • Presentation: Semantic HTML5 tags and CSS3 properties (Variables, Flexbox, Grids, and printing stylesheets).
  • Logic: Vanilla JS ECMAScript 6+ modules.
  • Database: Web Storage APIs (`localStorage` JSON tables).

6. Implementation & Quality Assurance

6.1 Codebase File Architecture

The project follows a clean directory structure containing dynamic HTML pages, shared script scripts, and CSS variable sheets:

  • `index.html`: Homepage with sliders and quick search widgets.
  • `flights.html` / `hotels.html` / `cars.html`: Dedicated booking category search lists.
  • `checkout.html`: Bundled cart overview and payment gateway simulator.
  • `login.html` / `dashboard.html`: Auth profiles, credit tokens manager, and voucher exports.
  • `css/style.css`: Variables layout stylesheets with a clean print layout format.
  • `js/db.js` / `js/auth.js` / `js/app.js`: Local database, secure token manager, and orchestrator scripts.
